# 图片生成

Plastic Wan 支持调用生图模型完成文字生图与参考图改图：聊天里模型自己决定何时调用 `image_generate`，生成完成后把图片作为相册发送到当前会话；管理员也可以直接在管理面板的图片工作台提交生成、翻查记录和整理图库。整条链路都经审计——每次生成有独立的模型与用量记录，每次发送计入消息审计。

## 启用图片生成

配置文件里没有 `image` 段时图片生成处于禁用状态，Bot 照常运行，只是模型看不到生图工具、面板不显示图片页面。启用有两种方式：

**方式一：管理面板（推荐）**。打开「图片设置」，按下面的步骤操作：

1. 勾选「启用图片生成」。如果已在 Models 页配置内置 OpenRouter，直接在「密钥来源」选择已保存的凭据，无需再次复制 API key；也可选择输入新密钥。已有图片凭据留空即可沿用。
2. 在「OpenRouter 图片模型」下拉框选择模型；也可以先按名称或 ID 搜索。列表自动从 OpenRouter 的图片模型 API 获取，失败时可点「刷新模型列表」重试，读取目录不需要 API key。
3. 选择供应商（默认选择首个可用供应商），点击「添加所选模型」。模型名称、内部 ID、路由标签、参考图上限、输出上限、比例和质量档位自动填好，无需去官网复制参数。可以继续添加其他模型。
4. 每个模型卡片上都有「用途与提示词备注」（最长 1000 字符），可以写下该模型适合的画风/任务与提示词风格偏好。备注供聊天里的 Agent 选型与编写提示词时参考；系统不会自动拼接备注原文，也不会把它作为独立字段发给生图服务。留空表示没有额外偏好，切勿填写 API key 或密钥。
5. 点击「保存并应用」，立即生效，无需重启。缺少模型或凭据时，按钮旁会说明需要补什么，点击也会提示原因。未填写的空凭据行会忽略；旧配置中完全相同的模型条目会在草稿中合并，保存后生效。重新打开页面会显示已保存的模型与凭据名称，密钥不会回显。

能力取所选供应商的元数据与本项目支持范围的交集。「自动」表示让上游决定；质量档位对应上游的 `quality`，仅提供像素分辨率选项的模型显示「自动」。要求必填参考图或仅输出 SVG 的模型暂不可添加，页面会显示原因。目录加载失败不会清空已配置的模型。

API key 明文只写入配置同目录的 key jar，`config.jsonc` 仅保留凭据引用。保存时如果其他页面或人工修改了配置，会提示冲突，请刷新页面后重试。

**方式二：直接编辑配置文件**。在 `config.jsonc` 中加入 `image` 段（凭据写 SecretRef，参见[配置说明](../reference/config.md)）：

```jsonc
{
  "image": {
    "credentials": {
      "openrouter": { "env": "OPENROUTER_API_KEY" }
    },
    "models": [
      {
        "id": "gpt-image-1",
        "name": "GPT Image",
        "description": "示例偏好：日常插画优先选用；用自然语言描述主体、构图和光线",
        "provider": "openrouter",
        "upstreamModel": "openai/gpt-image-1",
        "credentialRef": "openrouter",
        "providerTag": "openai",
        "capabilities": {
          "imageInput": true,
          "maxInputImages": 4,
          "maxOutputs": 4,
          "aspectRatios": ["auto", "1:1", "3:4", "4:3", "9:16", "16:9"],
          "resolutionClasses": ["auto", "low", "medium", "high"]
        }
      }
    ]
  }
}
```

改完文件后在面板「Settings」页点 **Apply config file** 应用。`image` 段的所有变化——包括启用与禁用本身——都是热更新，全程不需要重启。

已保存的有效图片配置会在服务重启时自动加载。若设置页显示已启用，但工作台仍显示禁用，检查服务日志中的 `image_service_warning`（例如凭据无法读取）；修复后在「Settings」应用配置即可恢复。

模型字段的含义：

| 字段 | 说明 |
| --- | --- |
| `id` | 模型标识，Agent 提交生成时用它指定模型；只配置一个模型时 Agent 无需选择 |
| `name` | 管理面板里显示的名称 |
| `description` | 可选，最长 1000 字符。供聊天里的 Agent 选型与编写提示词参考；系统不自动拼接原文，也不将其作为独立字段发给生图服务 |
| `provider` | 生图 adapter 的连接类型；当前内置 OpenRouter adapter |
| `upstreamModel` | 上游真实模型 ID（OpenRouter 格式，如 `openai/gpt-image-1`） |
| `providerTag` | OpenRouter 路由过滤标签，限定该模型只经此上游提供方路由 |
| `credentialRef` | 指向 `credentials` 里的条目名，其 API key 就是上游服务的密钥 |
| `capabilities.imageInput` | 是否支持参考图（图生图/改图） |
| `capabilities.maxInputImages` / `maxOutputs` | 单次生成允许的参考图数与输出张数 |
| `capabilities.aspectRatios` / `resolutionClasses` | 比例与质量档位白名单；Agent 只能从中选择 |

生图请求由内置 adapter 直连上游服务，不经过聊天模型的 `providers` 连接；`credentials` 里的 API key 就是上游服务（如 OpenRouter）的密钥。

## 在聊天里使用

启用后，直接在对话里提出画图请求即可，例如「帮我画一张霓虹雨夜的街景」或「把刚才那张照片改成水彩风格」。模型的完整流程是：

1. 通过只读的 `list_image_models` 查看当前模型目录，结合能力和备注选择模型、编写提示词；
2. 调用 `image_generate` 提交生成意图（提示词、模型、比例、质量、张数、可选参考图），立即返回一个生成编号；
3. 生成在后台进行（通常几秒到几十秒），完成后一条任务回执注入对话；
4. 模型用 `send` 把该次生成尚未交付的成品一起发出，单图直接发送、多图作为相册，可以附一句说明；也可以用 `send_reply` 先发图、再接几条文字讲解。

几点行为约定：

- **模型选择**：配置了多个生图模型时，模型会先只读查看当前模型目录（不会触发任何生成或费用），结合你的要求、每个模型的能力与备注挑选最合适的模型和提示词风格。你明确指定用某个模型时，只要它支持所需能力就会优先遵守；目录里没有或不再可用的模型不会静默换成别的。
- **参考图只能来自当前会话**：模型只能引用它在本会话中见过的图片（你发送的照片或历史图片），跨会话、过期或伪造的引用都会被拒绝。
- **同一请求不会重复计费**：同一会话里内容完全相同的重复提交会返回已有生成，不会向生图服务重复扣费；每个运行窗口最多提交 3 次生成。
- **已发图片默认不重复交付**：在线发送审计保留期间，同一会话里同一生成的同一成品不会因为重复调用或晚到的完成回执再次发出；服务重启后仍按发送记录判断。后来新增的成品仍可正常交付。你发一条新消息明确说「把刚才的图片再发一次」时，模型可以通过显式重发参数发送，但默认不能再次引用已经回复过的原消息（将 `agent.allow_reply_message_multiple_times` 设为 `true` 可放开引用回复限制，图片交付去重与结果未知保护不受影响）；参见[同一条消息只回复一次](../configure/telegram.md#同一条消息只回复一次)。
- **发送结果未知时不盲目重试**：网络超时不代表 Telegram 一定没收到。若此前发送仍在进行、结果未知，或升级后旧记录不足以确认发送了哪些图片，Bot 会拒绝再次投递，需要先核实；明确重发也不绕过这一保护。
- **失败会说明原因**：生成失败时模型会用自己的话解释；任一成品文件缺失或无法读取时，本次发送会整体拒绝，不会静默省略该图片再发送剩余成品。它不会在失败后反复重试，也没有绕过 `send` 的隐藏发图通道。
- 禁用图片生成后（面板关闭开关或删除配置段），模型与面板会立即失去图片能力，再次开启立即恢复。

## 管理面板三页

- **图片生成（工作台）**：编辑提示词、选择模型与参数，勾选提示词素材和参考图后提交；提交前可用「解析预览」查看引用展开后的最终提示词。生成过程实时刷新，同一提交重复刷新不会重复计费。
- **生图记录**：点击列表中的生成编号进入独立审计详情，也可直接打开 `/image-generations/<生成编号>`。详情包含状态、使用的模型、提交来源（管理员或哪个会话）、每次尝试的上游请求编号与用量、最终提示词、输出大图与错误信息。参考图按当时提交给模型的顺序展示，保留提交时的名称，点击可查看原图；素材归档后仍可查看，原图已清理或加载失败时会显示提示。支持重试失败的生成；点击「返回列表」回到生图历史。
- **图片资产**：提示词素材与参考图库。生成产物会自动进入图库；参考图支持上传（单个不超过 20 MB）、改名和归档，归档的素材不再出现在选择列表。

「图片设置」页就是启用开关所在：切换开关写入配置并立即应用；禁用时整个 `image` 段被删除，随之不再被引用的 key jar 条目也会一并清理。

## 保留与备份

生成记录、资产行随在线保留窗口（`retention.online_days`）清理，原图文件随数据目录清理。`backup` 在生成 SQLite 快照的同时，把原图目录一并快照为备份文件旁的同名 `.images` 目录——恢复时把两个文件放回原位即可，详见[备份与恢复](../operations/backup-restore.md)。
